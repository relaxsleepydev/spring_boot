# Basics of DNS

- **DNS (Domain Name System)** translates human-readable domain names, such as `example.com`, into IP addresses that computers use to find internet resources.
- A typical lookup involves four kinds of servers:
  - **Recursive resolver:** Receives the browser’s request and searches for the record.
  - **Root nameserver:** Directs the resolver to the relevant top-level domain server.
  - **TLD nameserver:** Directs it to the domain’s nameserver—for example, the `.com` server for `example.com`.
  - **Authoritative nameserver:** Holds the domain’s DNS records and returns the requested address.
- If the result isn’t already cached, the resolver follows these steps and returns the IP address to the browser. The browser then contacts the web server to load the page.
- DNS queries can be **recursive** (the resolver must find the complete answer or return an error), **iterative** (servers provide referrals to other servers), or **non-recursive** (the answer is already available, such as in a cache).
- **DNS caching** temporarily stores records in browsers, operating systems, and resolvers. Records are kept for a specified time, called the **time to live (TTL)**. Caching can speed up lookups and reduce repeated requests.

**In short:** DNS works like an internet directory, connecting memorable domain names to the IP addresses needed to reach websites.
